# MoSCoW Prioritization Guide

## Priority Tiers

### 1. MUST HAVE (Critical)
- Without this, the feature or release cannot launch legally, operationally, or technically.
- No viable manual workaround exists.
- Non-negotiable core functionality.

### 2. SHOULD HAVE (Important)
- Highly valued capabilities that enhance user experience significantly.
- An awkward or temporary workaround exists if omitted from initial launch.
- Target for subsequent sprint or minor version bump.

### 3. COULD HAVE (Desirable)
- "Nice-to-have" enhancements that provide marginal utility.
- Low development cost, but easily deferred if sprint velocity drops.

### 4. WON'T HAVE (Out of Scope for this cycle)
- Explicitly agreed not to be delivered in the current release window.
- Preserves sprint focus and prevents scope creep.
